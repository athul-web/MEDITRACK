# MediTrack Audit Report

Generated by static and documentation audit. No source files were modified. Dependencies were not installed, so build/type-check/runtime/browser tests were not executed; outcomes are recorded as environmental limitations.

## 1. Executive Summary

- Overall project health: **Mixed**. The codebase is substantial and includes both a public hospital-directory frontend and a protected equipment-maintenance dashboard, but several integration mismatches and partially implemented behaviors were found.
- Build: **Not verified** (dependencies not installed; `npm run lint` failed because `tsc` was unavailable).
- Runtime: **Not verified** (Vite dependencies absent; no `.env` with Supabase credentials observed locally; `.env.example` present).
- Core hospital workflow is at risk due to a database table-name mismatch: frontend repository queries `kerala_hospitals`, while seed SQL and available migrations use `public_hospitals` / `hospitals`.
- Most important issues:
  1. Hospital data source/table-name mismatch (`kerala_hospitals` vs `public_hospitals`).
  2. Hospital resource updates are optimistically recorded in `localStorage`, while the backend update is attempted against an uncertain column/table and failures are silently swallowed.
  3. Unsanitized user input is interpolated directly into PostgREST `or(...)` filters, enabling malformed-query/filter injection.
  4. Tailwind class typos in `HospitalList.tsx` produce invalid utility classes and missing text colors.
  5. Broad `anon` read policies may expose tenant equipment/problem-report data without authentication.
  6. No dependency installation/test execution possible in current environment.

## 2. Project Architecture

- Frontend: React 19, TypeScript, Vite 6, React Router v7, Tailwind CSS v4, Lucide icons.
- Backend: Supabase (PostgreSQL, Auth, RLS, Edge Functions) via `@supabase/supabase-js` directly from browser.
- Routing: `/` public home, `/hospitals`, `/hospitals/:id`, about/contact/legal, `/login`, `/dashboard` protected.
- Auth: Supabase Auth email/password; `AuthGuard` checks session; logout uses `supabase.auth.signOut()`. No registration UI or password reset implementation found.
- Public hospital repository: `src/data/repositories/supabaseHospitalRepository.ts` queries `kerala_hospitals`, maps snake_case→camelCase, Nominatim geocoding, OSRM distance.
- Dashboard: `src/App.tsx` loads `equipment`, `technicians`, `problem_reports`, `maintenance_records`, `notifications`, `facility_settings`, and `profiles` directly from Supabase.

## 4. Confirmed Bugs

### BUG-001 Highlight table-name mismatch for hospital data
- Severity: Critical/High
- Affected: `src/data/repositories/supabaseHospitalRepository.ts` (all methods), `src/lib/supabase.ts` (client calls)
- Lines: `getHospitals` ~11-18, `getHospitalById` ~20-28, `searchHospitals` ~55+
- Steps: Open `/hospitals` with configured Supabase backend provisioned by repository migrations/seeds.
- Expected: Hospitals load from backend.
- Actual: Frontend queries `kerala_hospitals`, but seed and available schemas reference `public_hospitals` (and internal `hospitals`), so queries likely return relation-not-found errors.
- Root cause: Inconsistent table naming across codebase.
- Recommended fix: Align frontend/migrations/seed on one table name, preferably via migration rather than code-only change.
- Evidence: `grep -Rin "kerala_hospitals"` only in source; `supabase/seeds/demo_hospitals.sql` inserts into `public_hospitals`.

### BUG-002 Hospital resource updates are not reliably persisted
- Severity: High
- Affected: `src/data/repositories/supabaseHospitalRepository.ts` `updateResources`
- Steps: Use "Report Update" from hospital details and submit.
- Expected: Resource statuses persist to backend and reload identically.
- Actual: localStorage is always written; backend update is wrapped in try/catch with console.warn; if backend column/table is unavailable, update is swallowed.
- Root cause: Optional backend state treated as best-effort without surfacing failure or verifying.
- Recommended fix: Make DB update authoritative and report errors; add schema migration/support or remove claim.
- Evidence: `try { await supabase.from(...) } catch { console.warn(...) }`.

### BUG-003 Unsanitized PostgREST filter injection in search queries
- Severity: Medium-High (security/reliability)
- Affected: `src/data/repositories/supabaseHospitalRepository.ts`, `searchHospitals`
- Lines: category/district/custom/query `.or(...)` construction.
- Steps: Enter filter text containing comma/parenthesis or characters meaningful to PostgREST.
- Expected: Input treated as plain text.
- Actual: Input concatenated into `.or('city.ilike.%...%,...')`, potentially malformed or altered filters.
- Root cause: No escaping/validation before building query expression.
- Recommended fix: Sanitize/escape commas and parentheses or use exact filters/parameterized patterns.
- Evidence: `query.or(\`name.ilike.%${trimmedQuery}%...\`)`.

### BUG-004 Invalid Tailwind arbitrary-value classes in HospitalList
- Severity: Low-Medium
- Affected: `src/components/hospitals/HospitalList.tsx`
- Lines: ~151, 153, 171, 194, 223, 225
- Pattern: `text-[var(--color-text-primary]` (missing closing `]`).
- Expected: Text color utility applied.
- Actual: Class is invalid; browser/Tailwind may ignore it and inherited/default color remains.
- Root cause: Typo.
- Recommended fix: Restore `]` in six class strings.

### BUG-005 Non-functional "Forgot password?" link
- Severity: Low
- Affected: `src/components/Login.tsx`
- Evidence: `<a href="#">Forgot password?</a>` with no handler.
- Recommended fix: Implement password reset flow or remove link.

## 6. Security Findings

- Overly broad anon read policies: Supabase schema in root allows anonymous SELECT on core tables (`technicians`, `equipment`, `problem_reports`, `maintenance_records`, `notifications`, `facility_settings`) and select others per migration, potentially exposing operational data if anonymous users can invoke.
- Public hospital resource report can alter availability from any client without authentication; backend authorization is unclear.
- User input interpolated into filters (see BUG-003).
- `facility_settings` upsert hardcodes id `1`, which assumes a singleton global settings table; combined with broad admin policies may affect cross-tenant settings in multi-tenant deployments.
- Anon key exposed in browser is expected but must be paired with reviewed RLS; environment absent.
- CORS is wide open (`*`) in Edge Function; acceptable for public form but should be limited if possible.

## Fixes Implemented

### FIX-001 Hospital table-name mismatch
- Root cause: Frontend queried `kerala_hospitals`, while schema/seed design uses `public_hospitals`.
- Files changed:
  - `src/data/repositories/supabaseHospitalRepository.ts`
  - `src/services/hospitalService.ts`
  - `src/data/repositories/supabaseHospitalRepository.test.ts`
  - `scripts/geocode-hospitals.mjs`
- Change: All runtime/query references were aligned to `public_hospitals`.
- Tests run: Unit test still cannot run because dependencies are not installed. Static grep confirms no remaining `kerala_hospitals` references in frontend service/repository code.

### FIX-002 Frontend and backend authorization for `/dashboard`
- Root cause: `AuthGuard` only checked for a Supabase session and did not verify role.
- Files changed:
  - `src/AppRouter.tsx`
- Change: Auth check now loads `profiles.role` and allows only `Staff` or `Admin`; otherwise routes to `/login`. Backend role enforcement remains through Supabase RLS/`profiles`.
- Tests run: Static/code review only; runtime verification unavailable due missing dependencies/env.

### FIX-003 PostgREST filter-string injection
- Root cause: Raw user input was interpolated into `.or(...)` filters.
- Files changed:
  - `src/data/repositories/supabaseHospitalRepository.ts`
- Change: Added `sanitizeFilterTerm` and applied it to district, typed location, and query filters; invalid/disallowed-character input is stripped before query construction.
- Limitation: This reduces injection/filter-shape risk, but safe PostgREST behavior with special search terms still requires integration testing against a configured Supabase instance.

### FIX-004 Resource updates and localStorage
- Root cause: `updateResources` always wrote local cache and swallowed backend failures, producing potentially false success.
- Files changed:
  - `src/data/repositories/supabaseHospitalRepository.ts`
- Change: Supabase update is now attempted first and `updateResources` throws on error; localStorage is only written after backend success. UI's existing error handling can display failures.
- Limitation: Public RLS must allow appropriate updates if this public workflow is intended; currently applied DB policies may reject anonymous writes. No database policy was changed.

### FIX-005 Malformed Tailwind classes
- Root cause: Missing closing bracket in six Tailwind class strings.
- Files changed:
  - `src/components/hospitals/HospitalList.tsx`
- Change: Corrected `text-[var(--color-text-primary)]` and `text-[var(--color-text-secondary)]`.
- Tests run: Static source inspection only; Tailwind build was not runnable due missing dependencies.
